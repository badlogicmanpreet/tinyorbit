tinyorbit

Architecture & the agent loop

A small terminal coding agent in Python (~6.5k LOC). You type a request; it calls a model over HTTPS; the model asks for tools; tinyorbit runs them locally and sends the results back, repeating until the model stops asking. Config & params flow down; events stream up. Only the model is remote: files, edits, shell, and permissions stay local.

2 · Consumers: who drives the loop & renders events

The loop yields events; a consumer is just a renderer. All are interface-agnostic below run_turn.

REPL (interactive)

Read-Eval-Print-Loop with Eval = the agent loop. Synchronous, line-oriented; an ANSI Renderer is the entire "print" step. Terminal ask() answers permission prompts.repl.py · run_interactive

Print mode (headless)

One-shot: task in, run to completion, exit. The shape for scripts, CI, and SWE-bench.repl.py · run_print_mode

Runtime (embedding seam)

Drive the loop as a library: a persistent session + an on_event callback receive the same event objects the terminal renders. No stdin ⇒ ask=None, decisions fall through like --print.runtime.py · Runtime

Outer loop (once per user message): run_turn appends the user message, builds QueryParams, does async for event in query(): render(event), then copies the final history back into SessionState. Nothing below it knows a terminal exists.
↓ QueryParams (messages · system · tools · ctx · provider · cost)

4 · Provider seam: model transport

The loop never imports a vendor SDK. It hands a neutral ModelRequest to provider.stream() and consumes a neutral event stream. providers/

resolve_provider()

Registry lookup by name → $TINYORBIT_PROVIDER → model-id heuristic. Unknown names trigger a lazy import providers.<name>, so an opt-in gateway self-registers.

Two orthogonal axes: dialect = wire format (Anthropic Messages · OpenAI Chat) · transport = endpoint + auth (first-party · Bedrock · gateway). ProviderCapabilities gates features so missing ones degrade, never error.

anthropic

Reference transport. SDK used only for SSE parsing, creds, typed errors: not its loop.providers/anthropic.py

openai

Chat dialect → canonical blocks via NormalizedMessage.providers/openai.py

bring-your-own ▸

A custom transport (a self-hosted LLM gateway, a Bedrock-invoke endpoint, a new wire dialect) drops in as providers/<name>.py and self-registers on first lookup. The loop, tools, and permissions never change.providers/base.py · Provider

5 · Tool execution & permissions

From tool_use block to tool_result block. Always returns a result (the API rejects an unanswered call). tools/execute.py · permissions.py

run_tool pipeline
find_tool→ abort?→ schema + validate→ PreToolUse hooks→ permission→ tool.call→ budget (30k)
permission chain: ask is the last resort
bypass mode→ explicit allow rules→ read-only tools→ acceptEdits (writes in cwd)→ ask the human
Concurrency: consecutive concurrency-safe calls run in parallel under one gather; unsafe calls are singleton groups, order preserved (Read-then-Edit stays ordered). Oversized output spills to disk with a preview + path.
↓ the tool pool (advertised to the model; filtered by allowed/disallowed globs)
